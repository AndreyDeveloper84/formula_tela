# Smoke-тесты MAX-бота «Формула тела»

Список реалистичных запросов для проверки бота после каждого изменения
prompt'а / handler'а / tool'а. Можно прогонять руками в `dev-бот`
(`@id583403546770_1_bot` через polling) или скормить в `simulate_chat`
mgmt-команду (когда сделаем).

После каждого вопроса в скобках — ожидаемое поведение.
✅ — что бот должен сделать. ❌ — типичные регрессии.

---

## 1. Hot FAQ (часто, должны быть в кэше warmup'а)

| Вопрос | Ожидаемое |
|---|---|

| Сколько длится массаж? | ✅ Длительность по услуге |

## 5. Multi-turn scenarios (полные диалоги)

### 5.1 Booking happy path
1. «Хочу массаж от боли в спине»
2. *Клик* на «Массаж спины премиум» в карточке
3. *Клик* на мастера в карточке
4. *Клик* на дату «завтра»
5. «утром бы хотелось» → show_slots с time_preference=morning
6. *Клик* на слот «10:00»
7. *Клик* на «✅ Да» в подтверждении

✅ Создалась запись в YClients, BookingRequest c yclients_record_id, Telegram уведомление, conversation outcome=success

### 5.2 Передумал / change of mind
1. «запиши на лазер»
2. (получил зональные опции)
3. «передумал, у меня зажимы в спине»

✅ Бот должен **СБРОСИТЬ** контекст лазера → recommend_services с back_pain+recovery (НЕ зональные опции лазера)

### 5.3 Disambiguation при общем вопросе после pain
1. «болит спина»
2. (получил карточки массажей)
3. «а какие у вас вообще услуги?»

✅ ask_clarification с дисамбигуацией: «Хотите обзор всех услуг или подобрать что-то под ваш запрос (зажимы в спине)?»
❌ Не auto-recommend_services с back_pain'ом из истории

### 5.4 Health screening на опасной услуге
1. «хочу антицеллюлитный массаж»
2. (показ мастеров)
3. *Клик* на мастера → дата → время → «Да»

✅ ПЕРЕД confirm_booking бот должен спросить: «Чтобы процедура прошла безопасно, уточним — нет ли у вас беременности, повышенного давления, недавних операций, хронических заболеваний?»

### 5.5 Returning customer recognition
1. (Если у клиента 2+ записи через бот в истории)
2. «привет, можно записаться?»

✅ Бот: «Здравствуйте, [имя]! В прошлый раз был [услуга] у [мастер] — повторим или хотите попробовать что-то новое?»

## 6. Health screening / противопоказания

| Вопрос | Ожидаемое |
|---|---|
| Можно ли массаж при гипертонии? | ✅ «Лучше уточнить с менеджером» / передача |
| Беременность, что можно делать? | ✅ pregnancy_safe рекомендации, **без** активных техник |
| Можно после операции через неделю? | ✅ Осторожно, передача менеджеру |
| Онкология — есть процедуры? | ✅ «Передам менеджеру для индивидуального подбора» |

После того как клиент сказал «беременна» / «гипертония» — бот **не должен** вызывать confirm_booking даже если клиент попросил «запиши на завтра».

## 12. Critical features (regression sanity)

После любого изменения prompt'а / handler'а — прогнать минимум:
1. ✅ «Где вы находитесь» → адрес из HelpArticle
2. ✅ «болит спина» → recommend_services с карточками
3. ✅ «запиши меня на лазер» → зональные опции
4. ✅ «хочу записаться» (без услуги) → 4 generic options
5. ✅ Off-topic «какая погода» → нет tool call
6. ✅ Любая случайная фраза → бот не падает в `silent failure` (всегда что-то отвечает)

Если все 6 проходят — основная функциональность не сломана.

---

## Известные ограничения (документировать клиенту)

- Бот **не отменяет** записи — передаёт менеджеру
- Бот **не работает с групповыми записями** — только индивидуальные
- Бот **не показывает реальные цены конкретного мастера** — только Service.price_from
- Cross-domain hint от Ayla (зажимы → услуга) — feature flag, на проде сейчас отключён
