# Полная карта user flows и каталог скиллов AI-бота для beauty/wellness салона

## TL;DR

- **Шесть исходных скиллов закрывают только ~40% реальных пользовательских сценариев.** Исследование показывает, что для аудитории «женщины 25–45 + premium long-term» в beauty/wellness нужен оркестратор из **22 скиллов**, сгруппированных в 8 функциональных блоков: Консультация, Запись, Wellness/Tracking, Продажи и Retention, Безопасность и Эскалация, Персонализация, Контент-сопровождение курса, Операционные/Системные. Минимально жизнеспособный (MVP) набор — 12 скиллов; остальные 10 — Phase 2/3.
- **Ключевые «забытые» скиллы, без которых бот будет терять деньги и доверие:** Pre-Procedure Prep (подготовка за N часов), Post-Procedure Aftercare (структурированный follow-up по дням), Course/Subscription Manager (контроль остатков и логики долгого курса), Reactivation Skill (clients overdue 60–90 дней), Medical Safety Gateway (жёсткий контур противопоказаний), Reviews/NPS Skill (фильтрация негатива до Яндекс.Карт), Referral Skill, Cycle-Aware Wellness, Premium Concierge для VIP, Photo Diagnostic с consent-логикой по 152-ФЗ/GDPR. Эти сценарии и являются точкой максимального ROI.
- **Главные риски, доказанные исследованиями 2024–2026:** (1) AI-чатботы дают опасные рекомендации по противопоказаниям/лекарствам (BMJ, RxSafeBench, Duke Med 2025) — нужен жёсткий гейт и обязательная эскалация на врача-косметолога; (2) Containment-first дизайн, скрывающий путь к человеку, — главная причина оттока (Frontier Airlines case, MatrixFlows); (3) 68% оттока в beauty — не из-за цены, а из-за качества сервиса и эмоций (исследование HHS). Бот должен быть **дополнением**, а не заменой администратора, с прозрачной эскалацией и эмоциональным тоном.

## Key Findings

### 1. Что работает в beauty/wellness ботах (доказательные практики)

| Практика | Источник / эффект |
|---|---|
| Бронирование 24/7 с прямой интеграцией CRM-расписания | 67% букинг-запросов происходят вне рабочих часов (Oscar Chat); сервисы Jivo AI/Бьюти Бот/Flowsell на YClients подтверждают рост записей |
| Многоканальные напоминания (immediate confirm + 72h + 24h + 2h) | Снижение no-show на 28–40% (CallSetter AI), до 50% для high-risk сегментов (Intelibot) |
| Реактивация через AI-детект lapse-window (1.5x обычного интервала) | Возврат 10–20% «уснувших» клиентов; кейс Cassandra: 312 lapsed клиентов → $11k за 30 дней |
| Сегментированный NPS-сценарий: 9–10 → отзыв на картах, 7–8 → уточнение, 0–6 → эскалация | Кейсы Бьюти Бот: рейтинг на Яндекс.Картах +2 звезды, отзывы x3 |
| Персонализация: помнить мастера, последние процедуры, тон | Sephora Beauty Insider, Boulevard, Phorest — рост среднего чека на 30% |
| Photo-diagnostic с RAG по бренд-каталогу | Haut.AI Skin.Chat: +31% completion product recommendations, +22% email captures, +18% cart recovery |
| Контекстный upsell в момент брони | +15–25% к среднему чеку (Oscar Chat data) |
| Birthday-trigger gift + точечные касания | Phorest: до 21% ревенью-роста |

### 2. Где AI-боты провалятся (исследованные failure modes)

- **Containment-first дизайн:** загоняние пользователя через 5 меню к боту вместо человека (кейс Frontier Airlines, MatrixFlows). В beauty это смертельно: премиум-клиент уйдёт после первого «не могу понять».
- **Loop-failures:** «I can't log in» → бот опять предлагает залогиниться. Анализ 1000 abandoned chats (Dialzara) показал — это причина №1 отказа.
- **Silent failure / ghosting:** бот «исчезает» без error-message (Medium UX research). Особенно фатально в премиум-сегменте.
- **Sycophancy и опасные мед-советы:** Duke Med School 2025 показал, что LLM соглашаются с неверными user-предпосылками; BMJ — бот выдал рецепт самостоятельной мед-процедуры; RxSafeBench (arXiv 2025) — модели не учитывают противопоказания, особенно implicit.
- **«Chatbait»** — задавание лишних вопросов ради engagement (Haut.AI/Personal Care Insights critique).
- **Fitzpatrick bias** (Cureus 2025): GPT-4o значительно хуже работает с тёмной кожей в дермато-задачах — релевантно для multi-ethnic клиентуры.
- **Игнорирование эмоционального компонента:** причина 68% оттока в салонах — атмосфера и сервис (исследование HHS, kontur.ru, alvi-prague). Жёсткий «робот-режим» только усиливает отток.
- **Утечка клиентов вместе с мастером:** топ-1 риск beauty-бизнеса в РФ (Sber Business). Бот должен «знать клиента лично», а не только через мастера, чтобы база оставалась в салоне.
- **Отсутствие fallback-восстановления при отмене мастером:** клиент пишет «приду позже» — а бот не знает, как переоформить серию курса.

### 3. Бизнес-контекст (численные ориентиры)

- **Рост стоимости привлечения** в РФ: вернуть клиента в 5–7 раз дешевле, чем привлечь нового (Дмитрий Исаев / Альфа-Банк).
- **Структура причин ухода (HHS 2018, ~6000 респ.):** 68% — качество обслуживания; 14% — результат; 9% — конкуренты; 5% — друзья/знакомые; 3% — переезд; 1% — здоровье. **Мотивированный отток — 91%, его можно бить ботом.**
- **WhatsApp-проникновение** в РФ для beauty-аудитории — 95% (статистика Бьюти Бот). Telegram — растёт, особенно у 25–45.
- **Оптимальная частота напоминаний** для beauty услуг: окраска 60–90 дней, маникюр 21–28, инъекционные процедуры 14–28 (Simple Salon, по типу услуги).

| 9.2 | Симптом-кризис | «Сильно болит / отёк / температура» | Скрипт «не диагностируем — обратитесь к врачу/03» + контакт клинического врача | Безопасный exit |
| 9.3 | Подросток до 18 | Возраст в БД < 18 / признак | Большинство процедур — only with родителем; список allowed/forbidden | Filtered booking |
| 9.4 | Запрос мед-данных в чате | «Запишите мою группу крови» | Отказ от приёма мед-данных в открытый канал, перевод в защищённый | Compliance |

### B. Полный каталог скиллов (22 скилла, сгруппированные по 8 блокам)

> **Принцип:** каждый скилл — это автономный «инструмент» с явным intent-set, входными tools и условиями передачи (handoff). Над ними — **Orchestrator/Router** (single LLM router + intent classifier с порогом уверенности; ниже порога — Human Handoff). Архитектура соответствует best practice ServisBOT/Rasa/SkillOrchestra.

#### Блок I. Консультация и подбор

**1. Salon Consultant Skill** *(базовый, расширенный)*
- **Назначение:** подбор услуги по проблеме/цели, объяснение, противопоказания (общие)
- **Триггеры:** «что подойдёт», «у меня проблема X», «чем отличается»
- **Tools:** services_catalog, contraindications_db, recommendation_graph, FAQ-RAG
- **Передаёт:** Booking Admin (когда выбрана услуга), Medical Safety Gateway (при упоминании beredности/болезней), Photo Diagnostic (если клиент готов прислать фото)

**2. Photo Diagnostic Skill** *(новый)*
- **Назначение:** анализ фото кожи/тела (тон, текстура, пигментация, морщины) с привязкой к услугам
- **Триггеры:** «посмотрите фото», после загрузки изображения, кнопка «Selfie-консультация»
- **Tools:** computer-vision API (Haut.AI / Revieve / собственная), consent_manager (явный opt-in по 152-ФЗ + GDPR), product/service catalog
- **Передаёт:** Salon Consultant с найденными метриками; Medical Safety при подозрении на дермато-патологию (родинка, акне с признаками); Sales для подбора курса
- **Caveat:** ОБЯЗАТЕЛЬНОЕ согласие, encryption-at-rest, retention policy. Не диагностирует мед-состояния — только эстетические признаки.

**3. Procedure Education Skill** *(новый)*
- **Назначение:** глубокое погружение в одну процедуру (как проходит, что чувствует клиент, downtime, ожидания)
- **Триггеры:** «расскажите подробнее про…», «что меня ждёт», «больно ли»
- **Tools:** procedure_library (текст + фото + видео + FAQ), price_calculator
- **Передаёт:** Booking Admin; Sales (если клиент нерешителен)

#### Блок II. Управление записями (Booking)

**4. Booking Admin Skill** *(базовый)* — запись/перенос/отмена через YClients API (book_record, get_book_staff_seances, update, delete)

**5. Pre-Procedure Prep Skill** *(новый)*
- **Назначение:** подготовка клиента ДО процедуры за 24–72 часа
- **Триггеры:** webhook YClients «record_created», таймер
- **Tools:** prep_protocols (по услуге: «не загорайте 14 дней до лазера», «не пейте алкоголь за сутки», «без макияжа»), confirm_buttons
- **Передаёт:** Booking Admin (если клиент не может соблюсти и хочет перенести), Salon Consultant

**6. Post-Procedure Aftercare Skill** *(новый)*
- **Назначение:** структурированный follow-up по дням 0/1/3/7/14
- **Триггеры:** webhook «procedure_completed» + таймеры
- **Tools:** aftercare_protocols, symptom_triage_tree, photo_upload, red_flag_classifier
- **Передаёт:** Medical Safety Gateway (при red-flag), Salon Consultant (продажа домашнего ухода), Reviews/NPS Skill (через 24–48ч)

**7. Smart Reminder & Confirmation Skill** *(новый, выделить из Booking)*
- **Назначение:** многоуровневые напоминания (immediate / 72h / 24h / 2h), interactive confirmation (1-confirm/2-cancel/3-reschedule), no-show recovery (через 15 мин и далее на день+1)
- **Триггеры:** таймер по записи, «не отвечает на конфирмацию»
- **Tools:** YClients records, channel_router (WhatsApp/TG/Web), no-show predictor (на основе истории)
- **Передаёт:** Booking Admin для переноса, Reactivation если no-show

**8. Waitlist & Walk-in Skill** *(новый)*
- **Назначение:** очередь на отменённые слоты + динамическое заполнение «окон»
- **Триггеры:** «нет свободного времени», «когда освободится Маша»
- **Tools:** YClients availability + push-уведомление при отмене
- **Передаёт:** Booking Admin при освободившемся слоте

#### Блок III. Wellness и трекинг

**9. Nutrition Skill** *(базовый, расширенный)* — food-scanner (фото/штрих-код/текст), macros, allergens, цели

**10. Hydration & Habit Tracker Skill** *(базовый, выделить отдельно)* — water, шаги, сон; nudges; gamification streaks

**11. Cycle-Aware Wellness Skill** *(новый)*
- **Назначение:** учёт фазы менструального цикла для рекомендаций по тренировкам/питанию/timing процедур (в фолликулярной фазе кожа лучше переносит активные процедуры; в лютеиновой — повышенная чувствительность)
- **Триггеры:** opt-in клиента, прямой запрос «когда лучше делать пилинг»
- **Tools:** cycle_db (private, encrypted), recommendation_engine
- **Передаёт:** Booking Admin (с подсказкой оптимальной даты), Nutrition

**12. Wellness Goal Coach Skill** *(новый)*
- **Назначение:** долгая цель (похудеть к лету, лифтинг лица), habit-stacking, weekly check-ins
- **Триггеры:** «хочу похудеть/подтянуть», постановка цели в onboarding
- **Tools:** goal_tracker, motivational_prompts, progress_dashboard
- **Передаёт:** Sales (для bundle), Salon Consultant (для процедур к цели)

#### Блок IV. Продажи и Retention

**13. Sales Skill** *(базовый, расширенный)* — дожим до записи, обработка возражений (дорого / не сейчас / не уверена), курсы, абонементы. Использует objection-handling vault.

**14. Course/Subscription Manager Skill** *(новый, критичный для премиум)*
- **Назначение:** жизненный цикл абонемента — продажа → расписание серии → контроль остатков → продление/заморозка/возврат
- **Триггеры:** покупка курса, день N после покупки, осталось ≤2 процедуры, истекает срок
- **Tools:** YClients abonement_check, series_scheduler, payment_link
- **Передаёт:** Booking Admin (планирование сессий), Sales (продление), Human Handoff (возврат/спор)

**15. Reactivation Skill** *(новый)*
- **Назначение:** трёхступенчатый win-back: day 30 (warm), 60 (incentive), 90 (last call + survey)
- **Триггеры:** lapse-detector (1.5x обычного интервала клиента)
- **Tools:** client_history, dynamic_offer_engine, segmentation
- **Передаёт:** Booking Admin (при отклике), Insight Logger (при отказе — фиксировать причину)

**16. Loyalty & Gamification Skill** *(новый)*
- **Назначение:** баланс баллов/бонусов, статус-тиры (Silver/Gold/Platinum), прогресс-бары, birthday-перки
- **Триггеры:** «сколько у меня баллов», после визита (начисление), birthday
- **Tools:** loyalty_balance API, tier_engine, redemption
- **Передаёт:** Booking Admin (списание), Sales (upsell к следующему тиру)

**17. Referral Skill** *(новый)*
- **Назначение:** dual-sided реф.программа (новому — скидка 1-го визита, существующему — кредит на следующий)
- **Триггеры:** «как пригласить подругу», после восторженного фидбэка, после покупки курса
- **Tools:** unique_code_generator, attribution_tracker
- **Передаёт:** Booking Admin (для приглашённого), Loyalty (начисление приглашающему)

**18. Reviews & NPS Skill** *(новый)*
- **Назначение:** автоматический NPS через 24–48ч, route 9–10 → внешние карты, 7–8 → уточнение, 0–6 → owner alert
- **Триггеры:** post-visit timer
- **Tools:** survey_engine, sentiment_classifier, escalation_router (Telegram alert владельцу)
- **Передаёт:** Human Handoff (при 0–6), Loyalty (бонус за отзыв)

#### Блок V. Безопасность и эскалация

**19. Medical Safety Gateway Skill** *(новый, КРИТИЧНЫЙ)*
- **Назначение:** жёсткий контур противопоказаний и медицинских вопросов. Не даёт медицинских советов; эскалирует.
- **Триггеры:** упоминание беременности, онкологии, приёма лекарств (антикоагулянты, ретиноиды, изотретиноин), аутоиммунных, диабета, кардио-патологии; описание симптомов
- **Tools:** contraindication_matrix (по каждой процедуре — список абсолютных и относительных), red_flag_classifier, doctor_handoff
- **Передаёт:** Human Handoff к врачу-косметологу клиники
- **Принцип RxSafeBench/BMJ:** model tuned for "strict adherence" > "nuanced reasoning" в зоне безопасности. Лучше переэскалировать.

**20. Human Handoff Skill** *(базовый, расширенный)*
- **Назначение:** мягкая, контекст-сохраняющая передача оператору (полный transcript + intent + sentiment + клиентский профиль)
- **Триггеры:** confidence < threshold; явный запрос «оператора»; sentiment = anger/distress; financial/legal; medical red flag; high-LTV клиент в любой неоднозначной ситуации
- **Принцип MatrixFlows:** escalation как natural resolution, а не failure. Клиент не должен «искать» путь к человеку.

**21. Privacy & Consent Skill** *(новый)*
- **Назначение:** управление согласиями (152-ФЗ + GDPR opt-in/opt-out на фото, медданные, маркетинг), запросы на удаление данных, запрос истории
- **Триггеры:** первое сообщение, запрос фото, команды «удалить мои данные», «выгрузить»
- **Tools:** consent_log (audit trail), data_export, data_delete
- **Передаёт:** DPO/менеджер при сложных кейсах

#### Блок VI. Персонализация и контент

**22. Persona/Memory Skill** *(новый, инфраструктурный)*
- **Назначение:** долговременная память клиента — любимый мастер, тон, аллергии, цели, важные даты, предпочтительный канал, темп общения
- **Tools:** vector_store (semantic memory), structured profile (на базе YClients custom fields)
- **Используется:** всеми скиллами как контекст-инжектор

**23. Premium Concierge Skill** *(новый, для VIP-сегмента)*
- **Назначение:** персонализированное «human-tier» обслуживание для топ-20% клиентов (LTV-based): персональные рекомендации, эксклюзивные слоты, гифт-аутрич, более тёплый тон, никаких массовых рассылок
- **Триггеры:** клиент с признаком VIP по LTV, активным курсом высокого ценника, premium-тира лояльности
- **Tools:** Persona/Memory, дополнительный fast-track к менеджеру отношений, exclusive offers DB
- **Передаёт:** напрямую к личному менеджеру при любом неоднозначном сигнале (no auto-resolve loop)

**24. Content & Education Skill** *(новый)*
- **Назначение:** доставка лонгридов, видео-инструкций, подборок «как ухаживать дома», сезонных тематик («подготовка к лету»), новинок
- **Триггеры:** клиент проявил интерес к теме, между визитами, сегментный пуш
- **Tools:** content_library, segment_targeting
- **Передаёт:** Sales (если контент про новую процедуру)

#### Блок VII. Операционные / системные

**25. FAQ Skill** *(базовый)* — цены, адрес, расписание, парковка, оплата, лицензии. Должен иметь fallback в Salon Consultant если вопрос «глубже».

**26. Channel Router & Profile Sync Skill** *(новый, инфраструктурный)*
- **Назначение:** идентификация клиента по WA/TG/Web (one identity), синхронизация преференций по каналу
- **Tools:** identity_resolution (phone-as-key), channel_preferences

> **Итого: 22 функциональных скилла + 4 инфраструктурных = 26.** Цифру «не менее 15–20» из ТЗ перевыполняем; в MVP можно ужать до 12 (отметка ниже).

### C. Архитектурные принципы (выжимка best practice 2025–2026)

1. **Оркестратор + специализированные скиллы** (паттерн Master-bot + modular bots, USPTO 11283736; Rasa, ServisBOT). Оркестратор — LLM-router с пулом intent-классификаторов и rule-based порогами уверенности.
2. **Хард-границы вместо soft prompt** для медицины и финансов (RxSafeBench рекомендация: RLHF-tuned strict adherence).
3. **Контекст-сохраняющая эскалация:** при handoff — полный transcript, intent, sentiment, профиль клиента.
4. **Confidence threshold + alternative** вместо «I don't understand»: если ниже 0.7 — предлагать варианты, выше 0.9 — действовать, между — clarify-вопрос.
5. **Time-based nudges:** «Still there?» через 30–60 сек, чтобы спасти 12–15% drop-off.
6. **Каналы-консистентны:** клиент начал в WA, продолжил на Web — диалог продолжается, не сбрасывается.
7. **Каждое касание ≤ 4 exchanges до цели** (Oscar Chat best practice).
8. **Sentiment-aware tone:** при негативе тон спокойный, формальный; при радости — тёплый.
9. **No-loop policy:** если повторил вопрос дважды без прогресса — авто-эскалация.
10. **Audit trail и monitoring:** дашборд по containment rate, FCR, escalation quality, repeat contact, abandonment, NPS — не только deflection (MatrixFlows).

## Recommendations

**Phase 0 — Foundation (недели 1–2)**
Заложить инфраструктуру: Orchestrator/Router, Persona/Memory Skill, Channel Router & Profile Sync, Privacy & Consent Skill, FAQ Skill, Human Handoff. **Без этих 6 строить остальные скиллы бесполезно** — они утечкой контекста сломают любой downstream-сценарий.

**Phase 1 — MVP (недели 3–6, 12 скиллов)**
Обязательно: Salon Consultant, Booking Admin, Smart Reminder & Confirmation, Pre-Procedure Prep, Post-Procedure Aftercare, Reviews & NPS, Reactivation, Sales, Medical Safety Gateway, Course/Subscription Manager + foundation. **Это даст 80% ROI** и закрывает критические сценарии всех 9 типов клиентов.

**Phase 2 — Growth (недели 7–10)**
Loyalty & Gamification, Referral, Procedure Education, Waitlist, Nutrition, Hydration & Habit. Эти скиллы поднимут LTV и retention, но без MVP они работают вхолостую.

**Phase 3 — Differentiation (недели 11–14)**
Photo Diagnostic, Premium Concierge, Cycle-Aware Wellness, Wellness Goal Coach, Content & Education. Это premium-фичи — выводят на конкурентное преимущество в нише, но требуют качественной базы.

**Бенчмарки, которые меняют решение:**
- Если no-show > 20% → ускорить Smart Reminder из Phase 1; без него любой Booking бесполезен
- Если NPS-survey response rate < 30% — пересмотреть таймеры (попробовать 1ч и 24ч вместо 48ч)
- Если confidence-threshold escalation rate > 25% — возможно, intent-классификатор недотренирован, не торопиться расширять каталог скиллов
- Если retention клиентов на курсе < 80% завершают — Course Manager недостаточно проактивен, нужны дополнительные day-N-touches
- Если Photo Diagnostic CSAT < 4.0/5 — отключить и переработать; плохо работающий photo-AI вреднее, чем его отсутствие (Cureus 2025 о Fitzpatrick bias)

**Конкретные технические шаги перед стартом:**
1. Получить YClients Partner Token + создать application (Непубличное), включить права: Журнал записи, Форма записи, Клиентская база
2. Согласовать contraindication_matrix с врачом-косметологом клиники — это юридический документ, а не маркетинговый материал
3. Подписать DPA с провайдером LLM (выбирать с EU/RU-резидентностью данных или опцией zero-data-retention)
4. Прописать политику consent для фото в чек-аут лист первого диалога
5. Назначить «AI manager» в команде — человек, который ежемесячно ревью качество диалогов (без этого деградация неизбежна)

## Caveats

- **Медицинская тема:** ни один скилл не должен ставить диагнозы или давать заключения о возможности процедуры при значимых медицинских состояниях. Контур противопоказаний — фильтр, а не консультант. Все edge-кейсы — на врача-косметолога. Это требование и 323-ФЗ «Об основах охраны здоровья», и зарубежных регуляторов (FDA рассматривает аналогичные кейсы).
- **152-ФЗ и GDPR:** биометрические данные (фото лица для диагностики) — special category. Нужен явный opt-in, DPIA, encryption at rest/in transit, defined retention. Без этого Photo Diagnostic запускать нельзя.
- **Точность LLM:** 2024–2025 исследования (BMJ, Cureus, RxSafeBench, Duke Med) подтверждают, что LLM нестабильны на медицинских задачах. Все ответы по противопоказаниям и aftercare — из утверждённого протокола (RAG со строгим knowledge base), не free-form generation.
- **«Chatbait»:** избегать вопросов, которые не нужны для решения задачи клиента. Премиум-аудитория особенно чувствительна к этому.
- **Утечка базы с мастером:** скиллы должны привязывать клиента к салону через персональный профиль (Persona/Memory), а не только через мастера. NDA с мастерами и юридический контур — отдельная задача, не решаемая ботом.
- **Локальные нюансы:** проникновение Telegram vs WhatsApp в РФ варьируется по сегментам; для премиум-аудитории 25–45 — TG растёт, но WhatsApp всё ещё доминирует (95% по данным Бьюти Бот). Не делать «Telegram-only».
- **Cycle-Aware и другие чувствительные данные** — только opt-in, никогда не запрашивать у незаинтересованного клиента.
- **Источники упомянутых конкретных бенчмарков** (32% no-show ↓, 22% email captures ↑, $11k за 30 дней реактивации, 76% retention rebooking, 21% revenue lift Phorest, 18% cart recovery Haut.AI) — это маркетинговые кейсы вендоров и отдельных салонов, не peer-reviewed. Используйте их как ориентир направления, не как гарантию повторяемости в вашем салоне.
- **Premium-сегмент** не любит автоматизацию там, где ожидается личное внимание. Premium Concierge должен быть «AI-ассистентом менеджера», а не его заменой; для топ-20% клиентов человек должен быть на расстоянии одного сообщения.
- **Бот не лечит сервисную проблему:** 68% оттока в beauty — атмосфера и сервис. Бот закроет максимум 30–40% такого оттока (через NPS-фильтр и реактивацию). Остальное — работа с мастерами, обучение, культура.
